Problem Understanding

The Limits of Game Dialogue & Why It Matters

1. The Core Problem

  • Traditional NPCs rely on rigid, pre-scripted dialogue trees.
  • Characters repeat themselves, forget player identity, and cannot adapt.
  • Player dialogue does not actually change physical world state.

2. Why It Matters

  • Static NPCs break player immersion and destroy replayability.
  • Indie/small studios cannot hand-write 10,000+ branching lines.
  • Games lack genuine emergent storytelling and emotional depth.

3. Scope & Assumptions

  • Scope: One deeply fleshed-out NPC ("Raghu"), one rural drought farm scenario, free-text + voice.
  • Assumptions: LLM API availability and sub-3s response latency.
Proposed Solution

Conversational Dialogue Driving Game Mechanics

💡 Project Idea

A web RPG where players converse with Raghu in natural language (EN/Hindi/Hinglish) with synchronized 2D lip movement and contextual hand gestures.

⚙️ How It Works

Player input + Raghu's persona + historical memory + world state are passed to the LLM. The reply returns dialogue plus structured game actions (quests, trust, inventory).

🎯 Minimum Deliverable

Free-text and voice conversation in character, unlocking quests, verifying real world actions, and visibly restoring the parched farm field state.

System Architecture

Inputs ➔ Processing ➔ Outputs Flow

[INPUTS] ───▶ [PROCESSING] ───▶ [OUTPUTS] • Typed Text or Voice (STT) • Express Server Pipeline • Dialogue Text & Voice (TTS) • In-Game World Actions • Prompt Builder (Persona+Memory) • 2D Lips Movement & Gestures • Rain, Gifts, Puzzles • Gemini Flash / Fallback Engine • Quests & Farm Health (0-100%) • Verification Flags • Strict Action Parser & Guards • Trust Meter (-10 to +10)

Deterministic Action Parser

The LLM proposes actions; the server validates physical prerequisites before mutating state.

Anti-Injection & Lie Detection

Catches dishonest claims ("I found your cow") against server flags; rejects prompt injections.

Feasibility & Risk Mitigation

Robustness, Latency & Fallback Engineering

Key Assumptions

  • Stable internet connectivity at the presentation venue.
  • Free-tier API rate limits accommodate demo traffic.

Identified Risks

  • LLM Latency & Outages: Slow API response.
  • Jailbreaks: Player forces NPC to break character.
  • Malformed JSON: Unreliable structured output.
  • Voice Synthesis Glitches: Inconsistent browser TTS.

Engineered Backup Plan

  • Rule-Based Offline Engine: Instant fallback simulation.
  • Provider Switcher: In-app API key & endpoint toggle.
  • Scripted Demo Chips: 1-click verified test buttons.
